Lesson 4 of 6 in Module 3

October 28, 2023· Development
Sean Dinwiddie

Mastering the fundamentals of Functional Reactive Programming (FRP) in software development requires a solid understanding of its core concepts and principles. Here’s a step-by-step guide to help you become proficient in FRP:

  1. Understand Events and Behaviors: Start with FRP’s two ideas: events, things that happen at a moment, and behaviors, values that change over time. In Redux Toolkit, the events are dispatched actions and the behaviors are selectors over the state.
  2. Learn Reducers and Selectors: A reducer folds each event into the next state, and a selector derives a value from state. Practice both as pure functions with plain inputs and outputs.
  3. Event Handling: Explore event handling in FRP. Understand how to react to events by dispatching actions named for what happened. Practice creating event-driven code that reacts to user interactions, data changes, or external events.
  4. Immutability: FRP often promotes immutability, where data is treated as unchangeable. Learn how to work with immutable data structures to maintain the purity of your functions and minimize side effects.
  5. Declarative Programming: Say what a value is rather than how to keep it current: a total derived by a selector, never a running total updated in a handler.
  6. Listeners: Study listener middleware, which reacts to later actions over time, and learn when to cancel work that has gone stale.
  7. Use Cases: Apply FRP to real-world use cases. Build small applications or features using FRP to gain practical experience. A cart, a menu that marks what sold out, or a booking calendar makes a good first one.
  8. Composition: Build larger functions from small ones with pipe and compose, and larger selectors from smaller ones. The lecture Functional Composition covers both directions.
  9. Testing: Learn how to test code written with FRP principles. Test a reducer through a sequence of actions and a selector through its output; neither needs a browser.
  10. Error Handling: Treat an expected failure, such as a declined card, as data, never as an exception: the client decodes what arrives into an Either in Endpoints at the Boundary, and the API refuses with its reason in One Feature, Scope to Launch.
  11. Connect the View: A React view reads shared state through useAppSelector and server data through RTK Query hooks, dispatches events, and keeps only local drafts in its own state.
  12. Performance and Optimization: A selector recomputes only when its inputs change, and a view that selects the narrowest value it needs re-renders only when that value does; measure a slow screen before changing its code.
  13. Read the Sources: The Redux Toolkit documentation and the Redux Style Guide set the current patterns, and Elliott and Hudak’s Functional Reactive Animation (1997) sets out behaviors and events.
  14. Ask Where the Patterns Live: Bring questions to the team’s own community and to the Redux documentation, whose guides teach the patterns this course builds on; general FRP forums mostly cover stream libraries, which model only events.
  15. Projects and Collaboration: Collaborate with others on projects that use FRP. Working on real projects allows you to apply your knowledge and learn from others’ experiences.
  16. Advanced Topics: Go on to advanced topics, such as effects over time with listener middleware, normalized entity collections, and FRP’s origin in continuous-time behaviors.
  17. Continuous Learning: The lessons are revised as the team’s practice improves; come back to them, and to Sean’s lectures, as your practice grows.

The rule behind the examples. The steps above come back to three pure pieces and one boundary. An event is a plain value that names what happened; the state is every event so far, folded through a pure function; a behavior is a value derived from that state; and every effect, from a network request to a timer, waits at the edge. Practice the three with no library at all:

// Events, a fold and a derived value, with no library.
type ItemAdded = { type: 'itemAdded'; productId: string; priceCents: number }
type Line = { productId: string; priceCents: number; quantity: number }

const next = (lines: Line[], event: ItemAdded): Line[] =>
  lines.some((line) => line.productId === event.productId)
    ? lines.map((line) => (line.productId === event.productId ? { ...line, quantity: line.quantity + 1 } : line))
    : [...lines, { productId: event.productId, priceCents: event.priceCents, quantity: 1 }]

const totalCents = (lines: Line[]) => lines.reduce((sum, line) => sum + line.priceCents * line.quantity, 0)

const events: ItemAdded[] = [
  { type: 'itemAdded', productId: 'widget-a', priceCents: 2500 },
  { type: 'itemAdded', productId: 'widget-b', priceCents: 1200 },
  { type: 'itemAdded', productId: 'widget-a', priceCents: 2500 },
]

totalCents(events.reduce(next, [])) // 6200

Redux Toolkit then adds what the fold leaves out: Immer for the update syntax, createSelector to remember derived values, the store to tell each view when to read again, and RTK Query and listener middleware for the effects. Learned in that order, each reads as a convenience rather than magic, and a reducer that misbehaves can be run by hand on a list of events. The lecture What Is a Function? starts from the same place.

Remember that mastering FRP is an ongoing process, and practice is key to becoming proficient. The more you work with FRP in practical scenarios, the more naturally you will derive what each screen shows from the events that happened.
